## 2026-03-02
### 1) 复盘记录
- 发生了什么：
  - 迁移后项目从“拆解+写飞书+Web预览”扩展到“选题库-初筛抓取维护 + Web 发起抓取任务”。
  - Web 在 UI 调整中出现过一次 500（Jinja 模板变量与 dict 内置方法名冲突），并多次出现布局挤压/溢出问题。
- 影响：
  - 用户在 `http://127.0.0.1:8101/?tab=prescreen` 无法确认“点击是否生效”、且部分区域可读性差。
- 处理过程：
  - 修复 500：避免在模板里使用 `xxx.items` 这类容易与 dict 方法冲突的变量命名。
  - 增强可观测性：Web 增加“任务状态 queued/running/done + 最近结果 + 最近写入预览”。
  - 布局修复：表单防挤压（label 不允许 shrink）、输入框允许收缩（min-width:0）、card/table 兜底 overflow。
- 当前结论/标准：
  - Web 的“动作型按钮”必须有即时反馈（banner 或状态区立刻出现 queued），避免用户误判“没反应”。
  - 任何列表/表格必须做溢出兜底（box-sizing + overflow-wrap + overflow hidden），否则长文本会破坏布局。
  - 飞书 select 字段优先写“可读 option 名称”，并对 option 做 clamp，避免写入 opt id 字符串污染表。
- 待办：
  - 若要继续提升初筛质量：补充更多平台来源（起点目前反爬），或引入“第三方榜单/聚合数据源”。

### 2) 工作模式和偏好
- 交互与确认：
  - 用户希望“真实流程真实执行”，并在飞书与 Web 中直接验收结果。
  - 当涉及编辑器操作（保存退出）与环境变量时，需要给出明确到“文件路径/命令/按键”的指引。
- 默认策略：
  - 生图默认异步（主流程只入队），worker 回填；降低单条失败对整批的影响。
  - 生成内容需严格社区合规（小红书避免引流嫌疑），提示词避免文字水印。
- 输出格式偏好：
  - 飞书表格中的值应“人类可读”（不要一串 option id/难懂字符串）。
  - Web 列表优先可读性（两行结构/标签胶囊/中文摘要），而不是把所有字段硬塞一行。

### 3) 经验和教训
- 技术层面：
  - Jinja 中 dict 变量名不要使用 `items/keys/values` 这类会和内置方法冲突的访问方式。
  - flex 布局要记得 `min-width:0`，否则子元素无法收缩会造成溢出。
  - Python 在某些环境写 `.pyc` 会触发权限问题：用 `PYTHONDONTWRITEBYTECODE=1` 更稳。
- 业务/流程层面：
  - 飞书字段搬迁（主表 -> 小红书笔记库）后，必须同步更新写入映射与 Web 展示；否则出现“字段空/没同步”的误判。
  - 初筛抓取的“入选维度/评分/收藏/评论”等字段必须可排序且解释清楚，否则不利于人工筛选。
- 可复用 Checklist：
  - Web 新增动作：必须有“提交成功提示 + 队列状态 + 最近结果”三件套。
  - 飞书写入：数值字段强制 float/int；select/multi-select 强制 option 名称并校验；新增字段先跑 schema ensure。
  - 内容合规：默认加入“禁止引流/禁止违规”约束；生图提示词默认禁止文字水印。
  - 分析旁路：1.1 必须与 1.0 解耦，先本地落盘（`logs/note_metrics_records.jsonl`），再可选写飞书。
  - 恢复期样本处理：周报建模应过滤低曝光极小样本（默认 `min_exposure=30`），避免误导结论。

### 2) 工作模式和偏好
- 交互与确认：
  - 用户希望“你来确定实验方案，我执行”，决策与执行分工明确。
  - 对内容要求：信息密度够，但不能平铺直叙，必须像真诚种草。
- 默认策略：
  - 先做真实运行验证，再做文档同步；避免“代码改了但流程没跑”。
  - 新增数据源优先独立数据表，避免污染既有口径。
- 输出格式偏好：
  - 需要可直接落飞书的操作结果（record_id/条数/字段是否成功）。
  - 文案偏好“可读、可抄、可发”，而不是报告腔。

### 3) 经验和教训
- 技术层面：
  - 飞书字段类型会被人工调整，写入前必须做按类型归一（single/multi/date/number）。
  - xlsx 导入不能假设单sheet；应基于 workbook.xml + rels 动态解析。
- 业务/流程层面：
  - 历史脏关联（失效主表ID）会导致内容来源不可追溯，需要定期体检修复。
  - 账号级趋势数据与笔记级数据需分层建模，不能混在同一表。
- 可复用 Checklist：
  - 新报表接入：先“字段探测->样本解析->schema补齐->真实导入->回查验证”。
  - 内容修复：先单条确认口径，再批量执行，最后产出修复报告。
