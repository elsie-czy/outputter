## 一、代码规范

### 1.1 Python

- 遵循 PEP 8
- 函数参数和返回值建议标注类型（不强求 Pydantic）
- 函数体不超过 50 行，超过考虑拆分
- 所有外部 API 调用必须有 try-except
- 禁止在代码中硬编码 API Key/Secret，统一走环境变量

```python
# good
def analyze_work(work: dict, reference_notes: list | None = None) -> dict:
    """分析作品并返回拆解结果"""
    ...

# bad
API_KEY = "sk-xxxxx"  # 禁止硬编码密钥
def analyze_work(work):  # 无 docstring
    ...
```

### 1.2 Flask 路由

- 所有新路由放在 `scripts/web/routes/` 目录，一个功能一个文件
- 使用 Blueprint 组织路由，设置 `url_prefix`
- 响应统一使用 `jsonify({"ok": True, "data": ...})` 格式
- 错误响应统一 `jsonify({"ok": False, "error": "..."})` + HTTP 状态码

```python
# good
bp = Blueprint("web_deconstruct_api", __name__, url_prefix="/api/deconstruct")

@bp.get("/queue")
def get_queue():
    try:
        items = read_queue()
        return jsonify({"ok": True, "data": items})
    except Exception as e:
        return jsonify({"ok": False, "error": str(e)}), 500
```

### 1.3 Jinja2 模板

- 页面模板继承 `base.html`，填充 `title` / `content` / `scripts` block
- 可复用 UI 片段用 Jinja2 宏，放 `templates/_components/`
- 模板中不上写复杂逻辑，数据处理在 Python 端完成
- CSS 类名统一 kebab-case

```jinja2
{# good: 继承 base，只写内容 #}
{% extends "base.html" %}
{% block title %}拆文中心{% endblock %}
{% block content %}
  {% from "_components/status_badge.html" import status_badge %}
  {{ status_badge(task.status) }}
{% endblock %}

{# bad: 在模板中写查询逻辑 #}
{% for t in tasks|selectattr("status", "eq", "done") %}  {# 筛选逻辑应在 Python 端 #}
```

### 1.4 Vanilla JavaScript

- 不引入任何 JS 框架（React/Vue/jQuery）
- 每个 JS 文件对应一个功能模块
- 使用 `fetch()` 调 API，`async/await` 处理异步
- DOM 操作用 `document.querySelector()` + `addEventListener()`
- 轮询用 `setInterval`，离开页面时 `clearInterval`

```javascript
// good: 模块化、轮询清理
class QueueList {
  constructor() { this.interval = null; }
  startPolling() {
    this.interval = setInterval(() => this.fetch(), 10000);
  }
  stopPolling() { clearInterval(this.interval); }
  async fetch() {
    const res = await fetch('/api/deconstruct/queue');
    const data = await res.json();
    this.render(data.data);
  }
}

// bad: 全局变量污染、无清理
var queue = [];
setInterval(function() {
  $.get('/api/deconstruct/queue', function(data) {
    queue = data;
  });
}, 10000);
```

### 1.5 飞书 API 调用

- 统一通过 `FeishuClient` 类调用，不直接写 http 请求
- Token 缓存复用，避免每次调 `get_token()`
- 飞书 API 限流 100 次/秒，批量写入时加 `time.sleep(0.1)`
- 字段值必须匹配飞书字段类型（Number 写数字、Select 写选项名）

### 1.6 JSONL 文件读写

- 使用 `scripts/utils.py` 中的 `read_jsonl` / `write_jsonl` / `append_jsonl`
- 写入时加文件锁（参考 `jimeng_worker.py:30-44`），防止并发写覆盖
- 队列文件追加写（不覆盖），游标文件覆盖写

## 四、错误处理与降级

### 4.1 外部调用必须有降级

| 调用 | 失败降级 |
|------|----------|
| LLM API（拆文/评分） | 重试 3 次，仍失败 → 返回本地 fallback |
| 飞书 API | 重试 1 次，记录错误日志，不阻塞主流程 |
| 即梦生图 | 异步队列重试 2 次，失败标记 `failed` |

### 4.2 超时机制

| 调用 | 超时 |
|------|------|
| LLM API | 120s |
| 飞书 API | 10s |
| 即梦生图 | 60s（提交）/ 300s（轮询结果） |

### 4.3 错误日志要求

每个错误日志必须包含：
- 时间戳
- 记录 ID 或作品名（定位上下文）
- 错误类型 + 原因
- 是否可重试

```python
# good
logger.error(f"[{rid}] 拆文失败: LLM 超时, retry={retry_count}/{max_retries}")

# bad
logger.error("failed")  # 无法定位
```

## 五、路径与配置管理

### 5.1 路径必须使用绝对路径

```python
# good: 基于项目根目录计算
BASE_DIR = os.path.abspath(os.path.join(os.path.dirname(__file__), ".."))
PATHS = {
    "data": os.path.join(BASE_DIR, "data"),
    "queue": os.path.join(BASE_DIR, "data", "queue"),
}

# bad: 相对路径
queue_path = "./data/queue"
```

- 配置文件中的路径在 `config.py` 中定义，不在业务代码中写死
- 日志中输出绝对路径便于排查

### 5.2 环境变量

- 所有配置通过 `.env` → `os.getenv()` 读取
- 绝不允许在代码或配置文件中硬编码密钥
- `.env` 在 `.gitignore` 中，不提交

## 六、边界条件检查清单

| 场景 | 检查项 |
|------|--------|
| 列表/数组 | 是否可能为空？遍历前检查 `if items:` |
| 字符串 | 是否可能为 None？用 `str(value or "")` |
| 数值 | 除法前检查分母 `if total > 0:` |
| 文件 | 是否存在？`if os.path.exists(path):` |
| JSON 解析 | 用 `try-except json.JSONDecodeError` |
| 飞书字段 | 是否存在？字段 ID 是否有效？ |
| LLM 返回 | JSON 是否完整？有 `_ensure_analysis_shape()` 兜底 |
| 队列消费 | 游标是否越界？空队列？全部失败？ |

## 八、任务开发要求

### 8.1 功能开发顺序

```
1. 阅读任务安排文档 → 确认改动范围
2. 先改数据层（JSONL 读写 / 飞书 schema）
3. 再改逻辑层（service / model_adapter）
4. 再改路由层（API Blueprint）
5. 最后改展示层（Jinja2 模板 + 静态资源）
```

### 8.2 每个阶段必须可验证

- 数据层写完 → 手动读写 JSONL 验证字段正确
- API 写完 → `curl` 验证响应格式
- 模板写完 → 浏览器验证渲染结果

### 8.3 禁止事项

- 在 `web_app_legacy.py` 上追加新代码（用新模板替代）
- 在 HTML 中内联 `<style>` 或 `<script>`（放 `static/` 目录）
- 在 Python 文件中写 HTML 字符串（用 Jinja2 模板文件）
